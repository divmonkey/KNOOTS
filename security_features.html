Zero-Trust Cryptographic Architecture

Technical specification detailing client-side end-to-end security protocols driving the KNOOTS offline-first ecosystem.

E2E AES-GCM-256

Your notes are encrypted in-browser using WebCrypto APIs before syncing to SQLite or Firestore. Decryption occurs strictly client-side.

  • Master keys are never uploaded or stored on servers.
  • PBKDF2 key derivation using SHA-256 and randomized salts.
  • Unique Initialization Vectors (IV) generated for every edit.
Biometric Credentials

Secure hardware unlock using WebAuthn APIs (TouchID, FaceID, Windows Hello) to cache key salts locally, keeping master vaults unlocked rapidly.

  • FIDO2 hardware-backed cryptographic challenge verifications.
  • Key salts stored securely inside browser session credentials.
  • Instant unlock without re-entering long master phrases.
Host Scope Isolation

Host servers only act as a synchronization medium, verifying OAuth identity tokens and storing encrypted payloads.

  • Google Identity credentials exchanged for secure JWT locks.
  • Database queries scoped strictly to user ownership IDs.
  • Asset uploads to Cloudflare R2 are client-side compiled and scoped.
Offline IndexedDB

Offline-first storage utilizes IndexedDB and local caches. Decrypted notes reside in temporary memory, never written to disk.

  • IndexedDB database entries remain fully encrypted.
  • Database schemas are isolated under secure IndexedDB indices.
  • ZIP Backups are compiled locally and encrypted in memory.
